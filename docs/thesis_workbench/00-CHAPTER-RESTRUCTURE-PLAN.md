# 论文章节重构计划（2026-04-15）

> 本文档记录对第3-5章系统设计与实现部分的重构过程，目标是调整结构，避免技术细节过度突出设计章节，使论文更符合"系统设计"的学位论文词汇规范。

## 问题背景

### 当前结构的问题
- **ch03-系统概要设计**: 内容还不错，但部分设计决策（如分页、返回结构约定）较技术导向
- **ch04-系统详细设计**: 存在过度技术化问题
  - 4.1 鉴权与权限控制设计 → 应该精简，技术细节（如OPENID、四步验证链路）太深
  - 4.5 错误码与异常处理策略 → 纯技术范畴，不适合系统设计章节
  - 4.6 数据库与索引设计 → 纯技术范畴，应当剔除或大幅简化
- **ch05-系统实现**: 内容基本可用，但缺乏详细的技术实现说明

### 用户反馈核心指向
> "数据库/索引设计、状态机、错误码、安全控制点这些东西太技术了，不应该写在设计里，最好也不要太突出这部分内容"

即：系统设计章节应该重点讲**业务流程与功能设计**，而非技术实现细节。

## 风险与注意事项

### 风险
1. **移除内容过多** → 导致系统设计章节过于简略
   - 缓解：保留一定的业务实现细节（如字段约束）

2. **新第5章过于技术** → 偏离"系统设计类论文"风格
   - 缓解：以"设计思考"为主，代码实现为辅

3. **章节间重复** → 系统设计、实现、关键技术中有交叉
   - 缓解：明确分工（设计讲"为什么"，实现讲"怎么做"，技术讲"细节与原理"）

### 注意事项
- ✏️ 修改章节号时需要同步所有交叉引用（图表号、小节号）
- ✏️ 保证代码位置映射真实无误（不虚构不存在的函数或字段）
- ✏️ 新第5章的表格与图示需要新建或从ch04转移
