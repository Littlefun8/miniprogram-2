# 6 小时执行计划（正式稿冲刺）

## 目标
在模板约束下完成一版可提交论文：章节完整、术语统一、图表齐全、内容与代码一致。

## 里程碑
- M1（0-60 分钟）: 完成事实基线、目录、任务拆分。
- M2（60-180 分钟）: 完成第 1-4 章主体草稿。
- M3（180-300 分钟）: 完成第 5-7 章、图表和关键表格。
- M4（300-360 分钟）: 全文统一与最终检查。

## 阶段任务
### 阶段 A：口径锁定
- 校正技术栈：微信小程序原生 + 腾讯云开发（非 Vue3/Vite）。
- 校正功能状态：`teacher_stats` 已接入 `getTeacherStats` 云函数。
- 校正实现边界：背书凭证上传、职位卡片 Canvas 等可作为展望。

### 阶段 B：正文生成
- 优先完成第 2/3/4 章（需求、概要、详细设计）。
- 第 1 章与第 5 章次之，第 6/7 章最后收尾。
- 每章按“设计目标 -> 实现方案 -> 工程价值”三段式。

### 阶段 C：图表与表格
- 必做图：架构图、总用例图、状态机图、ER 图。
- 可选图：发布审核时序图、申请处理时序图。
- 必做表：角色功能矩阵、云函数职责表、非功能需求表、数据库设计表。

### 阶段 D：收口
- 术语统一：校友/学生/教师、云函数、OPENID、状态枚举。
- 引用一致：章节结论能回溯到代码或文档。
- 模板检查：图表编号、目录、摘要、关键词、参考文献、致谢。

## 中断恢复原则
- 中断前必须更新 `00-PROGRESS-BOARD.md` 与 `06-handover/NEXT_ACTIONS.md`。
- 新窗口先看 `README.md`、`00-PROGRESS-BOARD.md`、`06-handover/HANDOVER-SESSION-01.md`。
