# 第3章时序图 Draw.io 绘制规格（按真实实现）

> 用途：把下面内容直接交给其他 AI 生成 **draw.io / diagrams.net XML 代码**。
> 输出要求：**横平竖直、正交连接线（orthogonal）**，不要 Mermaid。

---

## 0. 通用输出要求（必须遵守）

### 0.1 代码格式
- 请输出 **draw.io 可导入的 XML 代码**（.drawio / mxGraphModel 风格）。
- 每张图单独输出一个 XML 片段，或一个包含多页的 draw.io 文件也可以。
- 所有连线使用 **正交连接线**，避免斜线。
- 参与者按 **自左向右** 排列，生命线竖直向下，消息箭头水平推进，整体保持“横平竖直”。

### 0.2 版式要求
- 参与者（Actor/Object）放在同一水平顶端。
- 生命线（Lifeline）从上到下垂直延伸。
- 激活期（Activation）用细长竖条表示。
- 条件分支（alt/else/opt）用标准框或注释框表示。
- 页面、云函数、数据库三类对象分层清晰，避免重叠。

### 0.3 draw.io 连接线建议
- 连接线类型：orthogonal / elbow / segmented（优先正交）
- 箭头方向清楚，消息线尽量水平。
- 返回消息用虚线或浅色虚线。
- 条件分支用分区框标注“成功 / 失败 / 拒绝 / 重试”。

## 1. 图3-3 登录与角色确认时序图

### 1.1 参与者
- 学生 / 校友 / 教师（管理员）
- 微信客户端（登录页）
- `login` 云函数
- `setUserRole` 云函数
- Users 集合

### 1.2 关键流程
1. 客户端发起登录请求。
2. `login` 按 OPENID 查询用户信息。
3. `alt` 用户存在：返回用户信息与角色状态。
4. `else` 用户不存在：自动注册并返回空角色。
5. `opt` 角色为空：客户端进入角色选择流程并调用 `setUserRole`。
6. `setUserRole` 写入 `userType`，返回角色结果。
7. 客户端依据角色动态渲染业务视图。

### 1.3 异常分支
- 登录失败：显示错误提示并允许重试。
- 角色写入失败：提示用户重试。
- 已有角色：禁止重复设置。

### 1.4 draw.io 结构提示
- 左侧放 Actor，中间放页面，右侧放云函数与 Users 集合。
- `login` 在上，`setUserRole` 在下。
- `alt/else` 框放在云函数返回结果之后。

## 2. 图3-4 登录状态持久化与免登录识别时序图

### 2.1 参与者
- 用户
- 小程序启动流程 / 客户端
- 本地缓存
- `login` 云函数
- Users 集合

### 2.2 关键流程
1. 客户端读取 `isLoggedIn/userType/userInfo`。
2. 发起静默校验请求，调用 `login`。
3. `alt` 校验通过：恢复登录状态并进入首页。
4. `else` 状态缺失或校验失败：清理本地状态并跳转登录入口。

### 2.3 异常分支
- 本地缓存不存在。
- 服务端返回失败或账号状态异常。

### 2.4 draw.io 结构提示
- 本地缓存放在客户端旁边。
- 请求和响应箭头保持水平对齐。
- 异常分支用 `alt` 框显示“恢复成功 / 重新登录”。

## 3. 图3-5 职位发布入库时序图

### 3.1 参与者
- 校友
- 职位发布页
- `postJob` 云函数
- Users 集合
- Jobs 集合

### 3.2 关键流程
1. 校友填写职位表单并提交。
2. `postJob` 校验参数完整性与角色合法性。
3. 查询 Users，确认调用者是校友或教师。
4. `alt` 校验通过：写入 Jobs，状态设为 `pending`。
5. `else` 校验失败：返回错误并提示补全或调整内容。

### 3.3 异常分支
- 缺少必填字段。
- 用户未注册。
- 角色无发布权限。

### 3.4 draw.io 结构提示
- 左到右：校友 -> 页面 -> 云函数 -> Jobs/Users。
- 写入动作标注为“写入职位记录”。

## 4. 图3-6 职位审核流转时序图

### 4.1 参与者
- 教师（管理员）
- 审核页面
- `auditJob` 云函数
- Users 集合
- Jobs 集合
- Notifications 集合

### 4.2 关键流程
1. 教师提交审核动作（approve/reject）。
2. `auditJob` 校验教师身份。
3. 查询 Jobs，检查职位当前状态必须为 `pending`。
4. `alt approve`：更新职位状态为 `published`，写入通知。
5. `alt reject`：更新职位状态为 `rejected`，写入驳回通知。
6. 返回审核结果。

### 4.3 异常分支
- 非教师身份。
- 职位不存在。
- 状态不允许审核。
- 拒绝时缺少原因。

### 4.4 draw.io 结构提示
- 审核动作之后分成两个分支：通过 / 拒绝。
- 通知集合画在最右侧，作为结果写入目标。

## 5. 图3-7 职位列表与详情返回时序图

### 5.1 参与者
- 学生
- 职位列表页 / 详情页
- `getJobList` 云函数
- `getJobDetail` 云函数
- Jobs 集合
- Applications 集合

### 5.2 关键流程
1. 客户端按分页参数调用 `getJobList`。
2. 服务端返回列表、总数和 `hasMore`。
3. 客户端按 `jobId` 调用 `getJobDetail`。
4. `getJobDetail` 查询 Applications，判断当前用户申请状态。
5. `alt accepted`：返回完整字段。
6. `else`：移除联系方式、内推码、链接后返回。

### 5.3 异常分支
- 职位不存在。
- 详情请求缺少 `id`。

### 5.4 draw.io 结构提示
- 列表和详情两个请求分开画，但保持同一图中的调用链。
- 敏感字段门控放在详情返回前。

## 6. 图3-8 申请提交时序图

### 6.1 参与者
- 学生
- 职位详情页
- `applyJob` 云函数
- Jobs 集合
- Applications 集合
- Users 集合

### 6.2 关键流程
1. 学生点击申请。
2. 客户端提交 `jobId` 与可选背书信息。
3. `applyJob` 校验职位是否存在且处于 `published`。
4. 查询 Applications，执行 `jobId + userId` 重复申请检查。
5. `alt` 已申请：返回拦截结果。
6. `else` 未申请：写入申请记录、简历快照、职位快照和时间线。
7. 更新 Jobs.applicationCount。
8. 返回申请成功。

### 6.3 异常分支
- 缺少 `jobId`。
- 职位不存在。
- 职位不可申请。
- 重复投递。

### 6.4 draw.io 结构提示
- 重复检查放在写入前面，形成明确的并发控制链。
- 申请记录和职位快照画成两个写入节点。

## 7. 图3-9 申请处理时序图

### 7.1 参与者
- 校友
- 申请管理页
- `updateApplicationStatus` 云函数
- Applications 集合
- Jobs 集合
- Notifications 集合

### 7.2 关键流程
1. 校友选择处理结果。
2. 提交 `applicationId/status/remark`。
3. `updateApplicationStatus` 校验参数。
4. 查询 Applications 获取当前状态和 jobId。
5. 查询 Jobs，确认调用者是职位发布者。
6. 校验状态机：`pending -> processing -> accepted/rejected`。
7. 更新申请状态和处理信息。
8. 写入申请状态通知（最佳努力）。

### 7.3 异常分支
- 参数缺失。
- 非法目标状态。
- 申请不存在。
- 关联职位不存在。
- 非发布者无权限。
- 非法状态流转。

### 7.4 draw.io 结构提示
- 成功路径和失败路径都要画出来。
- 通知写入放在状态更新之后，作为附加结果。

## 8. 图3-10 申请进度查询时序图

### 8.1 参与者
- 学生 / 校友
- 进度页 / 管理页
- `getApplications` 云函数
- Applications 集合

### 8.2 关键流程
1. 客户端按角色发起查询。
2. 传入 `asPublisher`、`status`、`pageNum`、`pageSize`。
3. 服务端按 OPENID 构造查询条件。
4. 查询总数与分页列表。
5. 返回 `data/total/hasMore`。
6. 页面渲染状态与时间线。

### 8.3 异常分支
- 查询失败。
- 权限不匹配。

### 8.4 draw.io 结构提示
- 查询条件可在箭头旁标注。
- 列表数据返回后，右侧可画一个“状态时间线展示”对象。

## 9. 图3-11 通知生成与查看时序图

### 9.1 参与者
- 业务云函数（如 `auditJob`、`updateApplicationStatus`）
- Notifications 集合
- 通知页面
- `getNotifications` 云函数

### 9.2 关键流程
1. 业务处理完成。
2. 向 Notifications 写入消息。
3. 用户进入通知页。
4. 调用 `getNotifications` 按 OPENID 查询。
5. 返回通知列表、总数、未读数。
6. 页面展示消息。

### 9.3 异常分支
- 查询失败。
- 通知为空。

### 9.4 draw.io 结构提示
- 通知写入与通知读取要分清两个方向。
- 未读数可以作为返回结果旁注。

## 10. 图3-12 统计查询与返回时序图

### 10.1 参与者
- 教师（管理员）
- 统计页面
- `getTeacherStats` 云函数
- Users / Applications / Jobs 集合

### 10.2 关键流程
1. 教师打开统计页面。
2. 传入 `timeRange`。
3. `getTeacherStats` 校验角色是否为 teacher/admin。
4. 并行查询业务数据。
5. 计算总览、分布、趋势等结果。
6. 返回统计数据供图表展示。

### 10.3 异常分支
- 未注册。
- 角色无权限。
- 聚合失败。

### 10.4 draw.io 结构提示
- 数据查询和结果计算放在服务端一侧。
- 最右侧放“图表渲染”对象。

## 11. 最终给画图AI的通用指令

请按下面要求输出 draw.io XML：

1. 每张图单独输出一个可导入的 XML 片段。
2. 参与者从左到右排列，生命线竖直向下。
3. 所有连线使用正交连接线（orthogonal / elbow）。
4. 主流程使用实线箭头，返回使用虚线箭头。
5. `alt/else` 分支必须明确分组。
6. 不要画成 Mermaid，也不要画成流程图。
7. 图形尽量横平竖直，避免斜线和交叉线。
8. 标题使用“图3-x + 名称”。
