# 第3章 系统设计

## 3.2 总体架构设计
本系统采用“微信小程序前端 + 云函数服务 + 云数据库”的三层架构。前端负责页面展示与交互，云函数负责业务规则与权限校验，云数据库负责数据存储与查询，三层协同完成职位发布、审核、申请与统计等核心业务。

### 3.2.1 前端层设计
前端层基于微信小程序原生框架实现，负责页面渲染、交互事件处理和接口调用。该层以页面为组织单位，重点页面包括职位列表、职位详情、申请管理、通知中心与教师统计。

### 3.2.2 服务层设计
服务层由多个云函数构成，按“一类业务对应一个函数”方式组织。前端通过 `wx.cloud.callFunction` 调用服务，服务层在处理请求时完成参数校验、身份识别、角色判定和业务规则执行，并返回统一结构结果。

### 3.2.3 数据层设计
数据层采用云数据库，负责保存用户、职位、申请、通知等业务数据。数据层在本章重点体现数据对象与业务模块的对应关系，索引与字段级细节放在后续章节展开。

## 3.3 功能模块设计
为与第2章保持一致，系统设计仍按用户与权限管理、职位管理、申请与进度管理、通知与统计四个模块展开。模块之间通过页面调用与云函数接口形成协作关系。

图3-2 功能模块包图

### 3.3.1 用户与权限管理模块设计
该模块负责登录、角色确认与登录态管理。页面进入系统后先完成身份识别，再根据角色进入对应功能入口，避免不同角色越权访问。

模块交互以“页面请求登录 -> 服务端校验身份 -> 返回角色信息 -> 页面写入登录态”为主线。该模块适合使用简化时序图展示页面与云函数之间的调用关系。

### 3.3.2 职位管理模块设计
该模块覆盖职位发布、职位审核、职位浏览和职位详情展示。职位从发布到展示形成完整生命周期，审核结果决定职位是否进入前台可见范围。

模块交互以“校友提交职位 -> 教师审核职位 -> 学生浏览职位”为主线，适合用时序图表达多角色协作流程。职位详情中的敏感信息展示规则作为该模块子功能处理。

### 3.3.3 申请与进度管理模块设计
该模块负责申请提交、申请处理和进度查看。学生在职位详情中提交申请后，系统写入申请数据并生成状态；校友处理申请后，学生可在进度页查看结果变化。

模块交互以“提交申请 -> 处理申请 -> 回写状态 -> 查询进度”为主线，时序图可直观体现状态变化前后各方操作关系。
