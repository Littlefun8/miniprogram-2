# 第3章 系统概要设计

## 3.1 总体架构设计
系统采用微信小程序前端 + 腾讯云函数后端 + 云数据库的数据驱动架构。页面层通过 `wx.cloud.callFunction` 发起业务请求，云函数层负责参数校验、权限控制与业务规则执行，云数据库负责持久化存储。

该架构具备两点优势：其一，前后端职责边界清晰，敏感逻辑可集中在服务端；其二，依托云开发能力可降低部署和运维复杂度，适合在毕业设计周期内完成高可用原型。

## 3.2 功能模块划分
系统可划分为六个核心模块：

1. 用户与身份模块：登录、角色设置、个人资料管理；
2. 职位管理模块：职位发布、列表查询、详情获取；
3. 审核与背书模块：教师审核 pending 职位并回写审核结果；
4. 申请处理模块：申请创建、状态流转、进度展示；
5. 通知模块：关键操作触发消息通知；
6. 统计模块：教师端聚合统计与趋势展示。

## 3.3 核心业务流程设计

### 3.3.1 职位发布与审核流程
校友提交职位后，系统将其状态置为 pending；教师审核后，状态可变更为 published 或 rejected；学生端仅可见 published 职位。该流程在设计上将“发布权”与“审核权”分离，提升岗位可信度。

### 3.3.2 申请流转流程
学生提交申请后初始状态为 pending，校友处理后可进入 processing，最终到达 accepted 或 rejected。状态机设计避免了非法跃迁，保障流程可追踪性。

### 3.3.3 敏感信息解锁流程
职位详情中的敏感字段默认隐藏，仅当用户对该职位申请状态为 accepted 时返回。该机制在不影响公开信息浏览的前提下，控制内推权益暴露范围。

## 3.4 前后端职责划分
- 前端职责：页面展示、交互收集、请求云函数、状态反馈；
- 后端职责：身份识别、权限校验、业务规则执行、数据写入；
- 数据职责：按集合存储用户、职位、申请、通知、收藏与行为数据。

通过该分工，系统实现了“前端轻业务、后端重规则”的工程策略，降低了客户端被篡改导致的业务风险。

## 3.5 本章小结
本章给出了系统总体架构、模块划分与核心流程设计，明确了前后端边界与职责分工，为后续详细设计与实现章节奠定了结构基础。
