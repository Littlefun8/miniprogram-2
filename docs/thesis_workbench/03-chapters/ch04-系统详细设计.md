# 第4章 系统详细设计

## 4.1 鉴权与权限控制设计
系统采用微信云开发上下文中的 OPENID 作为身份来源。所有关键云函数通过 `cloud.getWXContext().OPENID` 获取调用方身份，避免信任前端传入 userId。角色权限通过 `users.userType` 字段进行服务端校验：例如教师审核接口只允许 teacher 角色调用，职位发布接口仅允许 alumni/teacher 角色调用。

在登录流程中，系统先调用登录云函数自动注册用户，再在首次交互中设置角色并持久化，形成“身份确定 + 角色确定”的双阶段控制机制。

## 4.2 职位模块详细设计
职位模块由发布、审核、查询与详情四部分组成：

1. 发布：校友提交职位表单，服务端按白名单构建职位对象，初始状态为 pending；
2. 审核：教师对 pending 职位执行 approve/reject，审核通过后状态变为 published；
3. 列表：列表接口默认查询 published 职位，支持分页、关键词和筛选参数；
4. 详情：详情接口返回职位完整信息，并根据用户申请状态动态控制敏感字段。

该设计将“业务动作”与“状态表达”统一到 jobs 集合中的状态字段，便于前端展示与后续统计。

## 4.3 申请与状态机模块设计
申请模块的核心目标是保证流程可追踪和状态可控。学生申请时，系统先校验职位状态与重复申请，再创建申请记录。申请记录包含以下关键字段：申请人标识、岗位快照、可选背书数据、时间线等。

状态机规则如下：
- pending -> processing
- processing -> accepted / rejected

系统在状态更新接口中校验当前状态与目标状态的合法性，不允许跨阶段跳转。通过该机制可防止业务绕过和异常状态写入。

## 4.4 敏感字段控制设计
职位详情中包含 `referralCode`、`contactWechat`、`jobLink` 等敏感字段。系统在详情云函数内先查询当前用户对该职位的申请记录，若状态非 accepted，则删除敏感字段后返回。该策略将数据保护逻辑放在服务端，避免仅靠前端隐藏造成泄露风险。

## 4.5 数据库与索引设计
系统核心集合包括：`users`、`jobs`、`applications`、`notifications`、`favorites`、`userActions`。数据库设计遵循以下原则：

- 字段采用 camelCase 命名；
- 状态字段采用字符串枚举；
- 高频查询路径通过组合索引优化。

索引设计重点在于提升列表与状态筛选性能，例如职位按状态和时间排序、申请按用户和状态筛选等。系统提供 `createIndexes` 云函数用于批量创建索引，并保留控制台手动兜底方案。

## 4.6 本章小结
本章从鉴权、权限、状态机、敏感数据控制和数据库设计五个方面展开了详细设计，构建了系统在“可用性 + 安全性 + 可维护性”之间的平衡方案。
