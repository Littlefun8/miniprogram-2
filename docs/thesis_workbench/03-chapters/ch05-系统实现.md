# 第5章 系统实现
## 5.1 前端页面实现
### 5.1.1 职位列表页实现
职位列表页是学生进入系统后的主要入口，承担职位浏览、筛选和分页加载功能。
**核心实现要点**：
1. **页面初始化与会话同步**
   - 页面加载时调用 `wx.cloud.callFunction` 获取用户登录状态
   - 同步本地缓存中的用户信息、当前角色等会话数据
   - 若用户未登录，引导跳转至登录页
2. **职位列表数据加载**
   - 调用 `getJobList` 云函数，传入分页参数（pageNum、pageSize）和筛选条件
   - 云函数返回已发布的职位记录及分页元信息（hasMore、total等）
   - 前端在列表组件中渲染职位卡片
3. **筛选与搜索交互**
   - 用户在搜索框输入关键词或通过下拉菜单选择城市、岗位类型、薪资范围等
   - 页面重新组织查询参数并调用 `getJobList`
   - 支持多个筛选条件的组合查询
4. **分页加载**
   - 初始加载第一页（pageNum=1，pageSize=10）
   - 用户滑动到列表底部时触发"加载更多"逻辑
   - 调用 `getJobList` 请求下一页数据，在前端追加到现有列表
该页面的实现重点在于**稳定性与响应速度**，而非复杂的动画效果。通过统一的列表加载逻辑，系统确保了用户体验的一致性。
### 5.1.2 职位详情页实现
职位详情页是学生了解具体岗位信息与进行申请操作的关键页面。该页面采用**状态驱动**的界面组织方式。
**页面状态与显示内容**：
| 申请状态 | 页面显示内容 | 关键按钮 |
|---------|-----------|--------|
| 未登录 | 职位基本信息（部分）| "登录" |
| 已登录、未申请 | 完整职位信息（无敏感字段）| "申请" |
| 已申请、状态pending | 完整信息 + 进度提示 | "已申请"（禁用） |
| 已申请、状态accepted | 完整信息 + 敏感字段 | "已通过" + 显示内推码 |
| 已申请、状态rejected | 完整信息 + 拒绝原因 | "已拒绝"（禁用） |
**具体实现流程**：
1. 页面进入时，调用 `getJobDetail` 云函数获取职位详情
2. 云函数检查当前用户是否已申请该职位及申请状态
3. 根据申请状态，返回不同内容（是否包含敏感字段）
4. 前端根据申请状态渲染对应的UI和按钮
该实现方式使**页面逻辑与业务状态紧密对应**，降低了维护复杂度，同时确保了权限控制的一致性。
### 5.1.3 申请管理页面实现
申请管理页面是校友处理应聘者申请的核心操作界面。
**功能实现**：
1. **申请列表加载**
   - 页面初始化时，调用 `getApplications` 云函数
   - 获取当前用户发布的所有职位下的申请列表
   - 支持按状态（pending/processing/accepted/rejected）筛选
2. **申请处理操作**
   - 点击某条申请，显示申请者的简历信息、职位快照等详情
   - 校友可以选择"接收"或"拒绝"
   - 调用 `updateApplicationStatus` 云函数更新申请状态
   - 若为"接收"操作，系统自动生成内推码并返回
3. **实时反馈**
   - 状态更新成功后，页面即刻刷新列表
   - 向申请者推送"申请已通过"或"申请已拒绝"的通知
### 5.1.4 教师统计页面实现
教师统计页面提供系统运营观察能力，聚合展示关键指标。
**数据展示**：
- **概览指标**：总职位数、总申请数、成功率、活跃用户数
- **职位分布**：按城市、岗位类型的职位分布图表
- **申请趋势**：按时间段统计的申请数趋势
- **排行榜**：校友发布职位最多的TOP 10、申请最多的职位排行等
**实现方式**：
1. 页面调用 `getTeacherStats` 云函数
2. 云函数负责聚合所有业务数据（jobs、applications表等）进行计算
3. 云函数返回已聚合的数据对象
4. 前端使用图表库（如ECharts）将数据可视化展示
这种**"后端负责计算，前端负责展示"**的分工避免了在页面层编写复杂的数据聚合逻辑。
## 5.2 云函数实现
### 5.2.1 登录与角色设置
**login 云函数**负责处理用户首次访问的初始化。
**实现逻辑**：
1. 通过 `cloud.getWXContext().OPENID` 获取用户的微信OPENID（可信身份来源）
2. 查询 `users` 集合，检查该OPENID是否存在
3. 若不存在，创建新用户记录，包括OPENID、创建时间、角色字段（初始为空）
4. 若存在，直接返回用户信息
5. 返回用户基础信息与登录结果（具体返回字段以云函数实现为准）
**setUserRole 云函数**处理用户角色首次绑定。
**实现逻辑**：
1. 获取调用者OPENID
2. 接收前端传入的角色选择（"student" / "alumni" / "teacher"）
3. 更新 `users` 中该OPENID的 `userType` 字段
4. 返回更新结果
5. 前端在成功后将角色信息同步到本地缓存
### 5.2.2 职位发布与审核实现
**postJob 云函数**处理校友发布职位的请求。
**实现步骤**：
1. 获取调用者OPENID，查询用户角色
2. 校验调用者是否为"alumni"或"teacher"，否则返回403错误
3. 从请求参数中提取**白名单字段**（下例为示意伪代码）：
   ```javascript
   const whitelistFields = {
     title: req.body.title,
     company: req.body.company,
     location: req.body.location,
     salary: req.body.salary,
     requirement: req.body.requirement,
     description: req.body.description,
     jobLink: req.body.jobLink,
     contactWechat: req.body.contactWechat,
     referralCode: req.body.referralCode
   }
   ```
4. 创建职位对象，设置初始状态为 `pending`、发布者为当前OPENID、创建时间等
5. 将职位记录写入 `jobs` 集合
6. 调用通知云函数，向教师群体发送审核通知
7. 返回职位ID与创建结果
**auditJob 云函数**处理教师对待审核职位的决策。
**实现步骤**：
1. 获取调用者OPENID，校验是否为教师角色，否则返回403
2. 接收职位ID与审核决策（approve / reject）
3. 查询 `jobs` 集合中该职位，检查状态是否为 `pending`
4. 若已被审核，返回409冲突错误
5. 审核通过时：
   - 更新职位状态为 `published`
   - 记录审核教师OPENID与审核时间
6. 审核拒绝时：
   - 更新职位状态为 `rejected`
   - 记录拒审原因
7. 向职位发布者发送审核结果通知
8. 返回审核结果
### 5.2.3 申请提交与状态更新实现
**applyJob 云函数**处理学生的申请请求。
**核心检查**：
1. 获取调用者OPENID（申请者）
2. 校验职位是否存在且状态为 `published`
3. **防重复申请**：查询 `applications` 集合，检查该OPENID是否已对该职位申请过
   ```javascript
   const existing = await db.collection('applications')
     .where({ userId: OPENID, jobId: jobId })
     .get();
   if (existing.data.length > 0) return { code: 409, message: "已申请过该职位" };
   ```
4. 若未申请过，创建申请记录：
   - 设置申请者OPENID、职位ID、初始状态为 `pending`
   - **快照存储**：保存申请时的学生简历数据（name, phone, email, resume等）
   - **职位快照**：保存职位标题、公司、薪资等
   - 记录申请时间戳
5. 返回申请ID与成功消息
**updateApplicationStatus 云函数**处理申请状态的推进。
**核心逻辑**：
1. 获取调用者OPENID（职位发布者）
2. 接收申请ID与新状态（processing / accepted / rejected）
3. 查询 `applications` 并获取关联的 `jobs` 记录
4. 校验操作者是否为职位发布者（publisherId），否则返回403
5. 校验状态转移是否合法（下例为示意伪代码）：
   ```javascript
   const legalTransitions = {
     pending: ['processing', 'accepted', 'rejected'],
     processing: ['accepted', 'rejected'],
     accepted: [], // 终态，不可转移
     rejected: []   // 终态，不可转移
   };
   if (!legalTransitions[currentStatus].includes(newStatus)) {
     return { code: 409, message: "非法状态转移" };
   }
   ```
6. 若转移合法，更新申请状态与更新时间
7. 若新状态为 `accepted`，生成内推码并保存
8. 向申请者发送通知
9. 返回更新结果
### 5.2.4 职位详情与信息保护实现
**getJobDetail 云函数**负责返回职位详情与权限控制。
**敏感字段门控逻辑**（示意伪代码）：
```javascript
const sensitiveFields = ['referralCode', 'contactWechat', 'jobLink'];
// 获取当前用户的申请状态
const application = await db.collection('applications')
  .where({ userId: OPENID, jobId: jobId })
  .get();
const appStatus = application.data[0]?.status;
// 若申请已接受，返回完整信息
if (appStatus === 'accepted') {
  return jobDetail; // 包含敏感字段
} else {
  // 删除敏感字段后返回
  sensitiveFields.forEach(field => delete jobDetail[field]);
  return jobDetail;
}
```
这种实现确保了**敏感信息只有在特定条件下才被返回**，从服务端层面保证了安全性。
## 5.3 系统部署与测试
### 5.3.1 部署流程
1. **代码准备**：确保所有云函数代码已完成、测试通过
2. **npm构建**：在WeChat DevTools中执行"构建 npm"，生成miniprogram_npm目录
3. **云函数部署**：
   - 在DevTools中右键每个云函数文件夹，选择"上传并部署"
   - 或使用腾讯云开发控制台批量部署（需注意handover文档中关于大量函数部署可能卡顿的提醒）
4. **环境配置**：验证app.js中的云环境ID是否正确（通常为 `cloud1-3g3q2srz04d1d705`）
5. **索引创建**：手动调用或运行 `cloudfunctions/createIndexes/index.js`，确保所有必要的数据库索引已创建
### 5.3.2 关键功能测试
**学生端测试路径**：
1. 未登录状态访问职位列表 → 应显示登录提示
2. 登录后选择"学生"角色 → 应进入职位列表
3. 浏览职位列表 → 应显示已发布的职位
4. 点击职位进入详情 → 应显示基本信息，但隐藏敏感字段
5. 点击"申请" → 应创建申请记录，重复申请应被拒绝
6. 申请被接受后 → 再次查看详情应显示内推码等敏感字段
**校友端测试路径**：
1. 登录并选择"校友"角色 → 进入校友主界面
2. 点击"发布职位" → 提交职位表单（白名单字段验证）
3. 职位进入"待审核"状态 → 等待教师审核
4. 教师审核通过后 → 职位状态变为"已发布"
5. 学生可申请 → 校友在申请管理页面收到申请
6. 校友处理申请 → 可选择接收或拒绝，状态转移符合状态机规则
**教师端测试路径**：
1. 登录并选择"教师"角色
2. 进入审核页面 → 显示所有待审核职位
3. 选择职位进行审核 → 点击"通过"或"拒绝"，状态更新正确
4. 进入统计页面 → 显示各类统计数据与图表
## 5.4 本章小结
本章从前端页面实现、后端云函数实现、部署流程和测试方法等多个维度说明了系统的落地方式。系统并非简单地把页面与函数堆砌在一起，而是通过**状态驱动的页面设计、白名单方式的参数处理、状态机的严格约束、服务端的权限控制和信息门控**等机制，将软件工程中的安全性、可维护性和可扩展性要求落实到具体实现中。这些实现策略确保了系统不仅在功能上完整，更在**架构稳定性和长期可维护性**上满足学位论文所要求的质量标准。
