# 论文章节自检模板（执行版）

> 用途：每次改写章节前后都要逐项打勾，避免重复犯错。

## A. 全文硬性约束
- [ ] 第2章/第3章/第4章模块口径一致：`用户与权限管理`、`职位管理`、`申请与进度管理`、`通知与统计`。
- [ ] 章节职责不串：需求章写“要什么”，设计章写“怎么设计”，实现章写“怎么实现”。
- [ ] 教师角色口径统一为“教师（管理员）”。
- [ ] 不引入与项目不符技术栈（如 Spring Cloud、Vue3 主栈、微服务网关）。
- [ ] 文风为本科论文语体，去除“AI腔”表达（如赋能、抓手、阀门等）。

## B. 图表先行规则
- [ ] 先写图表标题落位（`图x-y`、`表x-y`），再写正文和图表内容。
- [ ] 图号、表号与正文引用一致，无错号与跳号。
- [ ] 用例描述表优先使用纵向表（`字段 | 内容`），避免横向过宽。
- [ ] 图下注与表下注可统一为“来源：作者根据系统实现整理”。

## C. 微信小程序适配规则
- [ ] 设计章不强推类图，优先：包图/模块关系图、活动图、时序图、交互说明表。
- [ ] 交互链路必须体现：页面 -> `wx.cloud.callFunction` -> 云函数 -> 云数据库 -> 页面回传。
- [ ] 权限与身份描述基于真实实现：`OPENID`、`login`、`setUserRole`、`silentLogin`。

## D. 第2章（需求分析）自检
- [ ] 功能需求按模块小节写（不是零散功能堆叠）。
- [ ] 每模块包含模块总用例图与多个用例描述表。
- [ ] 术语偏用户视角：如“登录状态持久化”“免登录身份识别”。

## E. 第3章（系统设计）自检
- [ ] 结构从 `3.2` 开始，不单列 `3.1`。
- [ ] `3.2` 讲总体架构（前端层/服务层/数据层）。
- [ ] `3.3` 按四模块写模块设计与模块交互。
- [ ] `3.4` 写关键交互设计，使用时序图表达调用次序与状态变化。
- [ ] `3.3` 模块表采用“交互设计说明表”，不写“类设计说明表”。

## F. 第4章（系统实现）自检
- [ ] 仍按四模块展开，与第2/3章名称一致。
- [ ] 每模块至少包含页面实现 + 云函数实现 + 关键数据回写说明。
- [ ] 只写已实现能力，不把规划功能写成已上线。

## G. 最终提交前复核
- [ ] 章节间术语一致（需求/设计/实现/测试各用词符合角色视角）。
- [ ] 图表全部可定位到实际文件或已给出源码。
- [ ] Word 粘贴版排版可行（纵向表不过宽、标题连续）。
- [ ] 本轮新增改动已记录到过程文档（进度板或交接文档）。
